# 协同订单需求与实施顺序

状态：已记录的目标设计，尚未实现云同步。当前盘货仍为浏览器本地保存。本文不表示功能已经上线。

## 协作方式
用户随时提出点子与要求，由助手维护需求、判断依赖和安排实施顺序。无需每个常规设计选择都再次询问；遇到不能可靠推断的业务事实或账户部署限制时再解释并询问。

## 已确定的盘货交互
- 韩国食品45、中国食品66、其他18，三个分类子页面，各分类内保持原有按区域走动顺序。
- 本次不订：明确处理完成并前进；填写有效订货数量后点下一项完成；未作决定就跳过的保留待处理。
- 库存可不填写；空白不等于0。无重复实物确认勾选。特殊事项保留文字提醒。

## 新增目标：老板娘可协同编辑
1. 每次盘货拥有独立云端记录。分享该次记录的链接后，授权的老板娘在另一部手机可看到同一份数据，而不是空白本地草稿。
2. 老板娘具有编辑权限，不采用固定只读角色。权限保护用身份/访问控制、修改记录及恢复实现，不能用禁止编辑替代业务需求。
3. 汇总订单按韩国、中国、其他供应商分类。显示名称、已填库存及库存单位、订货数量及订货单位。未填库存显示未记录，不补0，不猜。
4. 订单汇总页直接编辑数量、增加/减少数量、将商品从本次订单移除。移除不删除129种商品目录、不删除历史库存；明确改为本次不订，可撤销。
5. 搜索覆盖全部129种商品，包括未订商品。结果显示已录库存、原订货状态和数量，可直接补订并加入当前供应商订单。中文/韩文均可搜索。
6. 用户和老板娘看到同一份协同订单。记录修改者、时间、前后值及版本，处理并发冲突，防止静默覆盖。老板娘修改订货量不自动改变用户记录的库存。
7. 盘货完成是提交给老板娘审核，不是不可编辑的最终发送版本。双方编辑后重新核对；对供应商发送时保存确定版本，后续改动提示需要补发。

## 分享与发送
- 分享给老板娘：受保护的协同编辑链接。
- 分享给供应商：仅该供应商的订货名称、数量、单位和日期/版本；默认不带内部库存或协同编辑权限。
- 每家订单同时提供复制和分享。优先调用设备原生分享菜单；用户自行选择KakaoTalk、聊天对象并确认发送。
- 能否出现KakaoTalk及联系人快捷入口取决于系统、安装应用和浏览器，不保证指定联系人直接出现。不把打开分享菜单/复制成功当作消息送达或供应商确认。
- 不支持原生分享时保留复制回退。只有原生分享无法满足时再评估Kakao官方SDK及其账户/域名配置。

## 实施顺序
A. 云端持久存储、身份/编辑权限、保存状态、备份恢复、冲突控制（所有协同功能的前置条件）。确定可部署方案后再承诺交付；当前GitHub Pages页面本身不提供云数据库。
B. 可编辑供应商订单汇总，带库存对照、全目录搜索、补订/减量/移除、撤销和修改记录。
C. 每次盘货的受保护分享链接，双方手机协同验收；发布/发送版本管理。
D. 原生分享与复制入口，iPhone到KakaoTalk实际验收。不自动向任何人发送消息。

## 验收重点
- 两部设备访问同次记录，看到相同已保存数据。
- 老板娘改数量，另一端可看见；并发修改不静默覆盖。
- 搜索未订商品后补订，正确出现在对应供应商订单。
- 删除本次订货行仍保留商品及库存记录。
- 空库存与0严格区分；库存与订货单位不混淆。
- 失败/离线显示未同步，不虚报保存成功。
- 供应商收到的是明确的订单文本/发送版本，不是内部编辑链接。
