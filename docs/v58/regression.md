# v58：新建空白盘货的存储配额错误

用户报告：在 iPhone 点击“新建空白盘货”，出现 `The quota has been exceeded.`，不能进入新表。

## 已复现的原因和修复边界

v57 的 `peerNewBlank` 在云端事务前调用 `peerKeepLocal`，每次向 localStorage 写入时间戳命名的完整恢复副本。配额不足时抛出未处理的原始英文异常，云端新建尚未执行。自动测试重现了这一确定失败路径；没有读取用户手机存储，不能断言该设备的全部占用来源。

v58 在刚完成服务器读取、文档ID、业务内容及目录都匹配时，不再额外写重复副本。云端 `newBlank` 原有事务仍原子保留旧未定稿盘货，再创建新表。该事务和安全规则没有放宽。不同本机内容仍需先保留；备份失败则停止并用中文说明，不清除任何已有恢复副本或未知存储键。

另修复云端新建后、本机保存失败仍被成功提示覆盖的问题：此时明确提示“云端已新建…但本机保存失败”，禁止再次新建直至保存状态恢复。
