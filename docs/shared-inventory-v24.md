## 已实现

- 对应已提交、待审核订单：盘货列表/搜索与订单列表/搜索使用同一份编辑内容；库存和订货均可编辑。
- 老板娘打开订单后可以在盘货页查看全部129项并修改。独立的新盘货草稿不与历史订单合并。
- 双方修改库存前确认，不填写原因；不自动改变订货数量。库存空白与0有区别。
- 盘货页复用订单页保存按钮、改动数量、正在保存、保存时间、失败与冲突提示。
- 审核定稿后两页均锁定，只能由老板娘重新开启。
- 库存修订保留在独立字段，保留原始快照、目录和订货单位；记录修改者、时间及库存前后变化。
- 库存可选单位与订货可选单位独立；备份恢复包含最新库存修订。
- 保存期间继续输入时保留后续输入；切换两页不丢失未保存修改；读取其他订单期间有新输入则停止切换。

## 数据与兼容

Firestore stockEdits 为按 units 键默认排序的逗号序列：~ 表示沿用原始快照，空项表示清空库存，0 为真实零库存。无库存商品必须为 ~。客户端解码为稀疏映射。stockUnits 只允许 cn:45 的模板库存单位。旧订单缺少这些字段时仍可读取。

Firestore 更新仍要求有效成员、递增版本和同一事务审计；原有老板娘不能篡改 snapshot 的限制保留。库存权限不扩展到未授权用户或未提交私人草稿。

上线顺序：先发布 firestore.rules，再合并网页补丁；双方刷新旧页面。旧页面不会显示新的库存修订，因此不能作为验收依据。
