# v43 · 搜索定位、分类文字预览、饮料供应商与库存单位

日期：2026-10-26。基于已经发布的 v42；修复用户当日录屏报告的操作问题。

## 修复内容

### 搜索结果随长订单滚动而消失

原实现只替换搜索结果区域，并沿用长订单的页面滚动位置。搜索框在固定栏内时，旧的定位代码直接返回。实际浏览器还复现了第二个因素：长列表缩成一条结果后，固定栏受父级内容区域限制，测得的当前位置也会暂时移到屏幕上方；仅使用该位置定位仍会遮住结果。

现在每次输入或清空搜索内容后，将结果区域定位到固定栏下方。定位使用固定栏声明的顶部位置与实际高度，并考虑可视区域，不依赖其暂时错位的坐标。输入框不被替换，中文、韩文输入及光标保留。进入搜索之前记住原分类与滚动位置；点击“返回订单”恢复它们。手机可视区域变化时不强行将用户手动浏览的搜索结果拉回第一项。

### 本类文字预览随分类变化

已打开的供应商文字预览保存所属分类；切换韩国、中国、其他、饮料时，在本机已确认的定稿版本上重新生成相应文字并显示于顶部。标题明确标识类别。空分类显示“这次不订”。预览的复制与分享验证当前订单、版本、会话、内容和分类，防止沿用其他分类或旧订单的文字。

切换与复制、分享不额外读取云端。打开另一份订单、读取新版本或解除定稿后，过期预览不会重新出现。链接分享保留原行为。

盘货、订单、搜索结果分类、分类计数、待盘跳转、分类末尾导航、文字预览及供应商复制/分享均采用同一分组。橙汁浓缩液保留在“其他”，中国供应商的饮料保留在“中国”。原来无需填写库存的饮料继续只填写订货数量。

分组由固定商品编号派生，原始目录和云端快照中的商品编号、主名称语言、顺序及底层类别保持原值，因此现有草稿、已定稿订单和历史记录可以直接使用，不需要改写生产数据。

### 库存单位

新建盘货默认库存单位：娃娃菜 `kr:31` 改为 `개`，水饺 `cn:21` 改为 `包`。订货单位仍分别为 `박스` 与 `箱`。库存和订货数量不进行自动换算。

已保存的旧盘货、已定稿记录以及恢复的历史快照，继续显示当时实际记录的单位和值，防止把旧的“箱数”直接重标成“个数/包数”。本次没有迁移或改写这些正式记录。

## 保留的规则

- 两个授权账号使用相同的共同盘货、定稿、解除定稿和供应商导出逻辑。
- 解除定稿继续停留在订单页；未定稿数量可在订单页修改，库存仍在盘货页填写。
- 定稿锁定、自动保存、明确保存按钮、备份恢复、权限和冲突保护保持原逻辑。
- 商品原主名称、已确认翻译及搜索别名没有改变。
- 复制和系统分享仍由用户选择发送对象，网站不自动向供货商发送消息。
