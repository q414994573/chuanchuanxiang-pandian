## 已实现的代码

- 原页面保留，`count-app.js` 只新增读取已复核盘货的桥接接口和更正分类复制文案。
- `cloud/` 是独立协同模块；构建后的 `cloud-app.bundle.js` 随 GitHub Pages 分发，不需要迁移托管。
- Firebase Authentication：Google 弹窗或普通邮箱密码。注册不授予订单权限。成员由项目所有者在控制台按 Firebase UID 授权。
- Firestore `members/{uid}`：`active: true`，`role: owner | editor`。客户端不能创建或修改成员表。owner 是盘货负责人，可新建订单；editor 可修改既有订单数量。
- `orders/{count-id}`：首次提交固定完整盘货快照、库存、商品目录与单位。后续更新只允许数量、版本、修改者、服务端时间、操作编号。
- `orders/{id}/revisions/{mutationId}`：每次保存必须原子写入完整版本，禁止客户端覆盖和删除历史。
- 保存采用 Firestore transaction：先比较读取版本，发生冲突则拒绝本次提交。事务重试也不会自动覆盖新版本。
- 重复提交按本机盘货 ID 去重；重复保存按操作 ID 去重。
- 读取使用服务端读取，未收到服务端确认不宣称成功。断网直接提示，长时间等待提示未确认，不以超时伪造失败或成功。
- 共享链接 `?order=count-…#count` 只标识订单，绝不作为授权凭证。
- 查询全部129种商品，按原始顺序；库存只读；清空数量或点本次不订只取消本次订货。
- 数量按千分之一单位整数编码保存（按固定 ID 排序的逗号序列；界面仍按原盘货路线显示，不改变商品顺序），避免小数浮点误差，显示原有单位。不能推测缺失单位。
- 最近50个版本可查看与载入待保存数量。恢复生成新版本，旧版仍留存。导出兼容本机盘货恢复的 JSON 文件；恢复时原模块会生成独立本机 ID。
- 分类复制前再次核对云端版本，预览并确认；不直接向 KakaoTalk 或任何供应商发送消息。

## 测试与发布命令

- `npm ci`
- `npm test`：原三组测试及新增数据/并发基础检查。
- `npm run test:rules`：仅在本地 `demo-ccx-collaboration` Firestore 模拟器运行。先测试3个模拟商品，再测试129规模；绝不连接生产项目。
- `npm run build`：编译前端；修改 cloud 源码后必须重建提交 bundle。
- `npm run rules:generate`：按原目录 ID 生成规则，目录变化后必须重新审计规则。此命令不修改商品数据。
