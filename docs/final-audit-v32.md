# 双账号共同盘货最终检查（v32）

日期：2026-10-22。正式入口保持 https://q414994573.github.io/chuanchuanxiang-pandian/ordering/ 。

## 结论与范围

在启用 sharedCounts 的正式 /ordering 入口，两名有效成员使用同一套页面和业务权限，共同维护 sharedCounts/current。任一方可盘货、改订货量、定稿、解除定稿、查历史、备份。没有老板娘审批阶段。同步成功后双方读取相同的当前盘货与订单；网络延迟、离线或冲突期间不能承诺两块屏幕瞬时一致。

本次执行了源代码审查、136项自动回归、原有权限规则模拟器测试及真实 Firestore SDK 双客户端共同盘货集成测试。没有使用真实营业订单做破坏性测试，没有实际登录两台用户手机进行同时操作验收。

## 仍需明确的边界

1. 尚未完成 iPhone 与三星、两个真实账号同时使用的真机验收；自动测试不能证明所有系统键盘、主屏幕缓存、剪贴板或分享弹窗行为。

3. 服务端读取核验与外部剪贴板/聊天软件发送不是一个数据库事务。核验后另一个成员仍可能修改；已复制到外部的文字无法撤回。发送前应看清日期与版本。
4. 规则校验成员、字段、版本和事务配对，JSON草稿内部语义由客户端验证；这不是针对恶意授权成员构造任意请求的完整安全认证，也不是“绝对无漏洞”承诺。
5. 旧私有草稿、历史记录原样保留。本次回退分支是代码与规则备份，不是整库快照；回退程序不能自动撤销之后发生的营业数据变化。
