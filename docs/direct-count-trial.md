# Direct counting trial

Open the Count tab or #count. New sessions preserve the catalog's existing order and start with blank stock and order quantities. Prior confirmed quantities are reference only. Explicit no-order decisions differ from pending entries; required stock/units, star physical checks and exception acknowledgements gate final review. Reviewed quantities are locked; editing requires reopening and reviewing again. Supplier copy is enabled only after complete review, and sent markers are manual, version-aware records, not transmission.

Storage: browser localStorage with per-session sequence checks, previous-save recovery, a per-tab undo stack and JSON backup export/import. Concurrent-tab changes block further edits. Failed saves produce a visible warning, preserve in-memory data for export and block finalization. Backups restore into a new independent session so existing records survive. Last focused product is saved. This is NOT authenticated cloud sync, and there is no Google Sheets writeback. Opening the page requires network; a loaded page can continue filling offline. Users should verify exported backups are saved before closing or changing devices. Keep the original spreadsheet for pilot verification.

Tests: `node tests/count.test.cjs` and `node tests/count-ui.test.cjs`. These test core review/quantity constraints, blank initialization, catalog order, immutable original data, backup round-trips, DOM-stub application startup, persistence failures, concurrent-tab conflicts, undo and non-destructive restore. They are not real browser/mobile visual tests. Real iPhone touch/keyboard QA remains outstanding.
